## 语种：中英日韩四套，结构必须逐位相同

README 有中英两版，各自配同语种的截图（英文成品带 `-en` 后缀）；日语/韩语没有对应的
README 版本，是给 X 等海外社媒素材用的。四语文案由 `demo-seed.py --lang zh|en|ja|ko` 选择。

**只换界面语言是不够的**：语言设置只改 UI 文案、不翻译已入库内容（这是产品的既定行为），
所以拿中文数据集拍英文界面会得到「英文 chrome + 中文内容」的**混语图**——比统一中文图更糟，
看着像只做了一半本地化。2026-07-30 之前 Ja/Ko 没有对应正文，拍摄脚本对这两个语种直接拒绝
（不悄悄拍出混语图）；同日补了日/韩两套真实翻译的正文后，四语均可正常拍摄。

四套之间**只有文字换语言，结构一律共用**：同样 12 条、同样 agent / 项目 / session /
时间戳、同样 kind、同样代号生命周期。结构一旦分叉，各语的版面与折行就不同，README
的中英两行（以及日/韩素材图）也对不齐了。`scripts/demo_dataset.py` 里因此把结构
（`NODES`/`CODES`）与文案（`CONTENT`/`DEFS`）分开存放，并有校验脚本核对「结构四语一致、
文案两两不同」（`scripts/check-demo-dataset.py`）。

⚠ **`kind` 与代号 `status` 落库的是中文 rawValue**（`需求`/`任务`/`定义`/`完成`/…），
两套都一样、**绝不翻译**：那是存储契约，界面靠 `UiText`（win）/ `UiText.swift`（mac）
映射成当前语言的显示标签。翻了会让 kind 过滤与代号状态机一起失效。

下表列**中文**一套；英/日/韩三套逐条对应，分别以 `scripts/demo_dataset.py` 的
`CONTENT['en']` / `CONTENT['ja']` / `CONTENT['ko']` 为准（翻译取自然表达，非逐字直译）。

## 拍摄要点

- 演示配置：摘要引擎=纯规则、全部 agent 开关关闭、回填 0 天（防真实 session 混入与
  LLM 调用）；replay 标记设为当前版本（防启动重放改写手工词典）；
  **界面语言必须钉死**（不能留「跟随系统」），且与灌注的数据集语种一致——否则产出语言
  取决于拍摄机的系统 UI 语言，而图看着完全正常（Windows 侧 2026-07-30 实测踩过）。
- 成品命名：中文不带后缀（`screenshot-<平台>-<态>.png`），其余语种带 `-en`/`-ja`/`-ko`
  （`screenshot-<平台>-<态>-<语种>.png`）。README.md 引中文、README.en.md 引英文；
  日/韩两套目前不进 README，只用于社媒素材。
- 期望画面：时间线含 4 色 agent 徽标与 kind 彩标；节点 #11 可见 `N2 ✓` `N3 △` chips；
  #8 为决策 kind（菱形锚点）；词典面板六代号全状态。
